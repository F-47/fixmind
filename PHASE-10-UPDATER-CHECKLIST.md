# Fixmind automatic updates checklist

The updater is configured in the tag release workflow, but it must not be enabled for users until the signing key is generated and the first signed update is verified.

## One-time key setup

- [x] Generate a Tauri updater key pair on a trusted machine. Keep the private key outside the repository:

  ```powershell
  npx tauri signer generate -w "$env:USERPROFILE\.tauri\fixmind-updater.key"
  ```

- [x] Store the private key and password in a password manager and in GitHub Actions secrets:
  - `TAURI_SIGNING_PRIVATE_KEY`: the private-key file contents (or a protected path available to the runner).
  - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: the private-key password, if one was set.
  - `TAURI_UPDATER_PUBLIC_KEY`: the complete public key text printed/generated by Tauri.
- [ ] Never commit the private key, password, or a generated `.sig` file.
- [ ] Treat loss of the private key as a release-blocking incident; existing installed versions cannot accept updates signed by a different key.

## Release workflow behavior

- [x] The workflow generates a temporary release config with the public key and the GitHub `latest.json` endpoint.
- [x] `createUpdaterArtifacts` is enabled only for signed releases.
- [x] The workflow signs updater bundles, publishes the `.nsis.zip`, `.sig`, and `latest.json`, then publishes the normal installer too.
- [x] Update checks use HTTPS and reject modified or unsigned artifacts through Tauri signature verification.
- [x] If any updater secret is missing, the workflow fails before publishing.

## User experience checks

- [ ] Start an older signed install and use the native “Check for updates” action.
- [ ] Confirm checking is asynchronous and does not delay dashboard startup.
- [ ] Confirm an available update can be deferred without changing the current install.
- [ ] Confirm “Install and restart” downloads, verifies, installs, and restarts the app.
- [ ] Interrupt a download or close the app during an update; confirm the old version still launches.
- [ ] Confirm lessons, settings, sync metadata, and `%USERPROFILE%\.fixmind` survive the update.
- [ ] Tamper with the update ZIP or signature in a test release; confirm installation is rejected.

## Rollback

- [ ] Mark a bad update release as a pre-release or remove its `latest.json`/assets.
- [ ] Publish a new higher version with the same updater key. Do not rotate the key for a normal rollback.
- [ ] If the key is compromised, revoke access, rotate the key deliberately, and plan a migration path for already-installed versions before shipping.
